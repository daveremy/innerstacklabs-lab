Why sprints at all?

Scrum was not the plan. The first sprint came from a request for sessions that end in a summary and a retrospective. Every later device was adopted reluctantly, one at a time, to answer a specific failure. The boundary does three jobs that an open queue tends to postpone:

Clear the context

Write a durable handoff and start fresh on a schedule, before the context fills and quality drops.

Count spillover

Unfinished work is saved and accounted for, not left to pile up silently.

Compare honestly

Committed against done, every two hours, which is what makes velocity and planning possible.

Start: check the commitment, lease the repositories, launch the first wave (median 0.6 min)

T−10: a timer outside the agent requests the wrap

T+20: a watchdog checks it wrapped

Before · sprint 43

The wrap timer lived inside the agent’s session. It never fired, and the sprint overran by about 100 minutes.

After · trigger outside the agent

58 of its last 60 firings delivered the wrap; 2 reported an error. It never interrupts a running step.

Who merges what

The team merges what its Definition of Done can judge

Ordinary, reversible changes in its leased scope, reviewed by risk, CI green. Most work.

No agent merges the rules that govern it

Instructions, skills, merge rules and gates go to the product owner.

Irreversible changes need the human’s yes

Money, auth, production data, releases. Collected at planning, so the sprint never waits.

When in doubt, ask

If the class is unclear, raise an impediment instead of guessing.

Authority follows the ability to judge consequences.

The one dangerous dependency: waiting for a person

5 h 12 min

22 Sep: one permission prompt in the CTO agent’s session halted the sprint cycle

15:45 → 21:53

26 Oct: an open question dialog; no backlog committed, the team idle 17:00 to 22:00

Decide at planning. A story needing approval carries the quoted decision.

The team never asks. A missing decision spills the story over.

Block only when it must. The human is typing now, and the answer gates the next step.

Pre-empt prompts. Permissions granted ahead; hooks refuse with a reason.

Where to start: five pieces

  1. A product-owner agent that talks with the human and plans
  2. A separate scrum-master agent that runs one sprint at a time
  3. Short-lived developer and reviewer agents
  4. A committed sprint backlog with a done condition per story
  5. A wrap trigger that lives outside the agents

Add everything else only as observed failures justify it. Persistent agents help but are not required: a timer that starts a headless scrum-master session every two hours is enough to begin.
